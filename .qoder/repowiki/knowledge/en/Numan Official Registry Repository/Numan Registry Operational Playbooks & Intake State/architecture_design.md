# Numan Registry Operational Playbooks & Intake State

This module is a flat collection of human-readable operational Markdown documents plus one machine-readable JSON state file (`intake-state.json`). The JSON defines schema version 1 with three top-level arrays — `ready`, `mirror`, and `blocked` — each holding package entries with fields like `id`, `name`, `owner`, `type`, `version`, `platforms`, `repo`, `spec`, and optional `pr`/`outreach` metadata; a `changelog` array records intake milestones. The `docs/outreach-issues/` subdirectory holds per-repo GitHub issue drafts (numbered `01-*.md` through `04-*.md`) that are copy-paste ready for filing against upstream maintainers, indexed by `README.md`. Procedural playbooks live as standalone Markdown files: `incident-response.md` (security triage, yank/revoke, rollback, user remediation), `key-provisioning.md` and `key-rotation-checklist.md` (signing key lifecycle), `lifecycle-prove.md` (verification workflow), `production-cutover-checklist.md` (release cutover), `upstream-release-outreach.md` (master outreach plan), `resign-after-highlight-source-backfill.md`, `roadmap.md`, and `intake-candidates.md`. Dependency direction is one-way: documents reference scripts and specs via relative paths but contain no executable code.
