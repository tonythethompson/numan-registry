Three cooperating JSON artifacts form a static, codeless registry with strict one-way dependency direction: specs → index → consumers.
- `schemas/index-v1.json` is a JSON Schema (draft-07) declaring the shape of the registry index, including package id (`owner/name`), type enum (`plugin`, `module`, `script`, `completion`), version metadata, artifact kinds (`binary`, `archive`, `source`), optional `source`/`dependencies`/`activation` blocks, and a `trust` block for key rotation via base64-encoded public keys.
- `registry/index.json` is the authoritative, signed index produced by merging individual specs; it declares `schema_version: 1`, an ISO 8601 `updated_at`, an opaque `registry_revision`, and a flat `packages` array where each entry carries `id.owner/name`, `description`, `repo`, `type`, `tags`, and a `versions` array pinning `nu_version`, listing `verified_with` Nu releases, and providing either a `binary` artifact (per-target `url` + `sha256` + `executable_path`) or an `archive` artifact with `entry`/`archive_root`. Some entries include a `source` block pointing to a git revision and `cargo_name`.
- `specs/*.json` holds one file per package-version pair (naming `<owner>-<name>-<version>.json`). These are the human-authored inputs that get merged into `registry/index.json`; they mirror the schema but without the top-level wrapper fields like `schema_version` and `registry_revision`.
- `registry/index.json.sig` is the detached signature over `index.json`, establishing a trust boundary between the signed index and its unsigned source specs.
Consumers validate the index against `schemas/index-v1.json` before trusting any package metadata; there is no runtime code in this module.
